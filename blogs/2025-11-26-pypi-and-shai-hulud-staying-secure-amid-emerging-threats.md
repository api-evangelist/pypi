<p>An attack on the npm ecosystem continues to evolve, exploiting compromised accounts to publish malicious packages. This campaign, dubbed <em>Shai-Hulud</em>, has targeted large volumes of packages in the JavaScript ecosystem, exfiltrating credentials to further propagate itself.</p> <p><strong>PyPI has not been exploited</strong>, however some PyPI credentials were found exposed in compromised repositories. We've revoked these tokens as a precaution, there's no evidence they have been used maliciously. This post raises awareness about the attack and encourages proactive steps to secure your accounts, especially if you're using build platforms to publish packages to PyPI.</p> <!-- more --> <h2 id="how-does-this-relate-to-pypi">How does this relate to PyPI?</h2> <p>This week, a security researcher disclosed long-lived PyPI credentials exposed as part of the Shai-Hulud campaign. The credentials were found in GitHub repositories (stored as repository secrets), and were still valid. We saw an attack with insecure workflow settings for <a href="../2024-12-11-ultralytics-attack-analysis/">Ultralytics in 2024</a>.</p> <p>While the campaign primarily targets npm, some projects use <a href="https://en.wikipedia.org/wiki/Monorepo">monorepo</a> setups, publishing both JavaScript packages to npmjs.com and Python packages to PyPI from the same repository. When attackers compromise these repositories, they can extract credentials for multiple platforms.</p> <p>We investigated the reported credentials and found they were associated with accounts that hadn't published recently. We've revoked these credentials and reached out to affected users to advise them to rotate any remaining tokens.</p> <h2 id="what-can-i-do-to-protect-my-pypi-account">What can I do to protect my PyPI account?</h2> <p>Here are security practices to protect your PyPI account:</p> <ul> <li> <p><strong>Use Trusted Publishing:</strong> If you are using a build platform to publish packages to PyPI, consider using a <a href="https://docs.pypi.org/trusted-publishers/">Trusted Publisher</a>. This eliminates the need to manage long-lived authentication tokens, reducing the risk of credential exposure. Trusted Publishing uses short-lived, scoped tokens for each build, minimizing the impact of any potential compromise. This approach has <a href="../2025-11-10-trusted-publishers-coming-to-orgs/">risen in popularity</a>, with other registries like <a href="https://crates.io/docs/trusted-publishing">Crates.io</a>, <a href="https://guides.rubygems.org/trusted-publishing/">RubyGems</a>, and <a href="https://docs.npmjs.com/trusted-publishers">npmjs.com</a> adopting similar models.</p> <p>When using GitHub Actions, consider layering in additional security measures, like requiring human approval via <a href="https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments">GitHub Environments</a> before publishing. <a href="https://www.pyopensci.org/blog/python-packaging-security-publish-pypi.html">This blog post from pyOpenSci</a> has detailed guidance on adding manual review steps to GitHub Actions workflows.</p> </li> <li> <p><strong>Audit your workflows for misconfiguration:</strong> Review your GitHub Actions workflows for any potential security issues. Tools like <a href="https://docs.zizmor.sh/">zizmor</a> and <a href="https://codeql.github.com/">CodeQL</a> can help identify vulnerabilities in your CI/CD pipelines. Adopt scanning as automated actions for the repository to catch future issues.</p> </li> <li> <p><strong>Review your account activity:</strong> Regularly check your PyPI account activity for any unauthorized actions. If you notice any suspicious activity, <a href="https://pypi.org/security/">report it to the PyPI security team</a> immediately.</p> </li> </ul> <p>Taking any of these steps helps mitigate the risk of compromise and keeps packages secure.</p> <h2 id="references">References</h2> <p>Some blog posts covering the attack behaviors and mitigation steps:</p> <ul> <li><a href="https://www.aikido.dev/blog/shai-hulud-strikes-again-hitting-zapier-ensdomains">Aikido</a></li> <li><a href="https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem">CISA</a></li> <li><a href="https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/">Datadog</a></li> <li><a href="https://helixguard.ai/blog/malicious-sha1hulud-2025-11-24">HelixGuard</a></li> <li><a href="https://www.reversinglabs.com/blog/shai-hulud-worm-npm">ReversingLabs</a></li> <li><a href="https://socket.dev/blog/shai-hulud-strikes-again-v2">Socket</a></li> <li><a href="https://www.stepsecurity.io/blog/sha1-hulud-the-second-coming-zapier-ens-domains-and-other-prominent-npm-packages-compromised">StepSecurity</a></li> <li><a href="https://www.wiz.io/blog/shai-hulud-2-0-ongoing-supply-chain-attack">Wiz</a></li> </ul>
